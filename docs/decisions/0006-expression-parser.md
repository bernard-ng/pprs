# Expression parser and initial public API

Accepted 2026-10-16. The library now parses the expression/file subset using the production lexer and the frozen PHP-Parser grammar. Functions, closures, arrow functions and control flow were added by the [statement and callable parser](0007-procedural-parser.md). The [declaration parser](0008-declaration-parser.md) added declarations, namespaces and anonymous classes. Unsupported syntax emits an error and cannot produce strict success.

## Public contract

`parse(input, options)` copies caller bytes after checking the input budget. `parse_source(source, options)` reuses shared source storage. Both return `Result<ParseResult, InputTooLarge>`; a result owns source, lossless tokens, diagnostics and a complete or partial `Program`. `parse_strict` returns `Result<ParsedFile, StrictError>`: `Input` reports preflight rejection, while `Parse` retains the entire non-clean result. This refines the draft single-error signature to preserve the lexer's input-limit-before-allocation guarantee. Strict means no recovery/error/resource stop, not PHP compiler or historical-version validation.

Supported statements are empty files, inline HTML, comments/no-ops, expression statements, echo/short echo, return, blocks and outermost `__halt_compiler`. Expressions cover literals and interpolation; names and unevaluated magic constants; variables; arrays and destructuring; unary, binary, assignment, reference, ternary and coalesce operators; calls, named/reference/unpacked arguments and first-class placeholders; dimensions and dynamic/static/nullsafe members; construction and cloning; casts, include/require, eval, print, isset/empty, exit/die, throw, match and yield forms. This initial subset did not support callables or anonymous-class bodies.

The private parser uses recursive descent and Pratt binding powers, with no general backtracking. `operators.rs` records the binding table, including PHP 7 versus PHP 8 concatenation. Assignment targets and argument/reference contexts have explicit grammar checks. Reference acceptance is not equivalent to writable PHP at execution time: the frozen parser accepts examples such as `f() = 1`, nullsafe assignment and scalar elements in destructuring. PPRS follows that grammar rather than adding a compiler pass. Complex clone and exit argument lists use function-call nodes as in the reference; ordinary `clone($x)` remains a unary operation. No PHP code or magic constant is evaluated.

Existing Logos scanning, literal utilities, byte strings and error types are reused. There are no new runtime dependencies. Recursive parser calls transfer boxed expressions, limiting native stack frames; owned child boxes also prevent expensive subtree copies. The AST remains typed and exposes source/token metadata. Auxiliary argument, item, match-arm and interpolation text nodes have their own metadata. `visit::walk` is an iterative preorder iterator that visits these nodes in grammar/source order and reports one-based depth. Grouping updates origin ranges without inventing a grouping AST variant. The later [source fidelity audit](0009-version-source-fidelity.md) verifies metadata and comment attachment.

## Recovery and budgets

Missing operands can create `ExprKind::Error` without consuming a delimiter. Missing terminators are inserted at unambiguous expression/statement boundaries; other failures synchronize over balanced delimiters to a terminator, block boundary or echo/return/HTML anchor. Progress guards prevent retrying the same token. Blocks restore scope even when parsing fails. The initial expression parser provided only best-effort recovery across callable and declaration syntax. The statement, callable and declaration parsers add their own recovery boundaries. The [diagnostic and recovery review](0010-diagnostics-and-recovery.md) covers malformed-file behavior and diagnostic differences.

Invalid Unicode escapes retain an expression error node and continue parsing. The reference aborts its entire tree in these cases. All eight affected reference corpus fixtures have exact alternate structure/status snapshots and reasons in the live coverage ledger. Invalid octals retain the reference's zero value with an error; malformed doc-string indentation strips the available prefix while diagnosing the failure. No invalid literal is silently accepted as clean. These choices preserve subsequent valid statements and always fail strict conversion.

Input, token, node, diagnostic and depth budgets apply cumulatively. Root and auxiliary AST nodes count toward the node budget, including constructed nodes later discarded during recovery. AST depth is checked with the iterative traversal independently of recursive grammar depth; grammar depth is conservatively counted and includes the root. The effective parser depth is `min(configured_depth, 128)` even if the caller requests more, protecting native stack use. The [robustness measurements](0011-robustness-and-performance.md) subsequently confirmed this limit. Partial retained trees remain within configured node/depth limits. A terminal resource diagnostic aborts parsing, and the cursor retains the unscanned suffix plus EOF without further scanning. The reserved diagnostic slot includes lexer and parser errors together. A regression test covers a token-budget stop during block recovery; stopped cursors are never queried again.

Halt handling uses the validated lexer boundary before scanning the payload. Valid outermost syntax preserves arbitrary trailing bytes, including invalid PHP and non-UTF-8. Malformed or nested halt syntax does not switch to raw-tail mode. Standalone lexing keeps its four documented differences; parser-level halt probes verify the authorized path separately.

## Evidence and coverage

- 133 dedicated, reproducible reference observations include 100 precedence cases across all ten targets, every expression operator family, expression contexts, interpolation, file boundaries, blocks and halt tails. These compare exact normalized trees and completion status offline.
- The reference corpus structure channel now has 69 exact matches and eight explicit Unicode recovery differences owned by the expression parser. No expression-grammar structure channel remains pending.
- Of the complete files initially assigned to expression parsing, eight also required functions or control flow and 24 required declarations or anonymous classes. Their structure comparisons moved to the statement and declaration parsers. Only their live structure ownership changed, with reasons. Frozen reference baseline inventories and reference corpus observations are unchanged. Focused expression probes cover the expression portions of these mixed files.
- Token coverage remains 296 exact streams plus four standalone-halt differences. At that point, all 300 complete cases still awaited position, comment and diagnostic comparisons. The node ledger's `slice` status means expression construction exists, not full family compatibility.
- Tests check caller-independent ownership, strict failures, traversal order, malformed-expression recovery, every truncation of the focused non-precedence probes, all 300 core files for invariants, 512 arbitrary-byte/small-budget cases, and deep parentheses/operators/arrays/calls/matches/interpolation/blocks. Three failures found during development (native stack size, recovery after resource abort and the trailing-comment depth check) have deterministic regressions.
- `parse_bytes` adds a bounded libFuzzer target alongside `lex_bytes`. The initial checks compiled the target; the later [robustness report](../benchmarks/robustness-performance.md) records instrumented campaigns.

Reproduce the oracle with `php -n -d short_open_tag=0 tools/parser/export.php --check` after verifying the pinned reference/runtime. Ordinary Rust CI reads committed fixtures and needs no PHP. See the [oracle contract](../../tests/fixtures/parser/README.md) and [tests](../../tests/parser.rs).

Local validation passed on stable Rust and Rust 1.85.0: 55 unit/integration tests and three doctests per toolchain. Formatting, Clippy with warnings denied, rustdoc, independent consumer checks, both fuzz-target builds, 13 Python tooling tests, frozen-reference verification, coverage non-demotion and reference, strategy, lexer, literal and expression oracle reproduction passed. Hosted CI and instrumented fuzz campaigns are not claimed.
