# Reference development tooling

Normal `cargo test` reads committed snapshots. These tools prepare and audit them; they are not a product binary or runtime dependency.

## Pinned oracle setup

Use **64-bit PHP CLI 8.5.6** with tokenizer and JSON, Python 3.9+ and Git. The exporter rejects another PHP version or integer width. Install that exact PHP release separately from the Rust crate. It runs with `php -n` (no loaded/scanned INI), short tags disabled, precision 14, serialization precision -1, C locale and UTC. These settings and extension availability are recorded in the corpus manifest.

The existing `.references` checkout is pinned by `reference/lock.json`. For a fresh checkout only:

```sh
git clone --no-checkout https://github.com/nikic/PHP-Parser.git .references
git -C .references checkout --detach 8d2b672aff65a1a4dbf7936cec27d19f51989412
```

Keep that checkout clean; do not install a Composer vendor tree there. The oracle needs no third-party PHP packages: an isolated PSR-4 autoloader loads the pinned library and `CodeTestParser`. The small `canonicalize()` helper is attributed to and adapted from upstream `test/bootstrap.php`, avoiding its PHPUnit/Composer bootstrap requirement. All 668 reference-file hashes are verified **before** upstream code is loaded or fixture macros are evaluated. The Python entry point also checks the clean Git commit/tree and P00 inventories.

This invokes the reference parser and trusted fixture macros only. Parsed fixture application code is never executed. No arbitrary fixture path or macro input is accepted by the exporter. `inputs.json` source bytes are parsed, not evaluated.

## Verify and regenerate

From the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/reference/verify_p00.py
php -n -d short_open_tag=0 tools/reference/test_export.php
PYTHONDONTWRITEBYTECODE=1 python3 tools/reference/export.py --check
```

`--check` generates into memory/a temporary directory, validates it and compares every generated byte to the committed corpus. It fails on dirty reference files, original dump mismatches, changed runtime, bad locations, missing bytes, exporter drift, or stale snapshots. This is an execution of all 290 parser fixture expectations, not the entire upstream PHPUnit suite.

For an intentional exporter/schema/input update:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/reference/export.py --write
PYTHONDONTWRITEBYTECODE=1 python3 tools/reference/corpus.py --write-report
cargo test --locked --test compatibility
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/reference -p 'test_*.py' -v
PYTHONDONTWRITEBYTECODE=1 python3 tools/reference/export.py --check
```

The exporter validates the complete staged output before writing its fixed file set. Review the snapshot diff, hashes, targets and counts; never automatically accept a new oracle expectation to mask a Rust regression. Coverage states are outside the generated tree and never rewritten by this command. New cases need explicit states before the offline suite can pass. Runtime/schema changes require a deliberate profile update and renewed adapter checks.

The importer uses upstream order: canonicalize raw fixture bytes, evaluate trusted macros, split sections, then extract modes. Expanded source is never canonicalized again. Full original fixture files and expanded original dumps remain alongside explicit-target observations. Encoding and comparison details are in [the corpus contract](../../tests/fixtures/README.md).

## Test layers

- `test_export.php`: independent expected values for macro expansion order, mode parsing, invalid UTF-8/NUL, integers/floats, comments, empty origins, CR/LF mapping and diagnostic end conventions. Requires the pinned oracle.
- `test_corpus.py`: offline importer/provenance and coverage negative checks, including missing cases and modified files.
- `tests/compatibility.rs`: offline Rust corpus reader, byte reconstruction/range invariants, independently specified adapter edge cases, deliberate comparison mutations, and active-state regression gates.
- `test_verify_p00.py`: immutable P00 metadata regressions.

Regular CI runs the Rust and offline Python layers. Oracle regeneration is an explicit local development check; it is not downloaded or executed during a Cargo build. Host PHP availability does not change parser compatibility states.
